## 继续工作的具体问题

1. 群消息普通 UIA 行只暴露正文，无发送者子控件，导致成员无法识别，不能通过 @ 自动回复的触发校验。
2. 已在微信实机验证：进入消息“多选”后，同一原生消息行变为 CheckBox，名称会增加发送者前缀；退出后恢复正文。下一步需以同一 runtime ID、类型和前后完全一致的正文建立独立发送者证据，拒绝正文伪装、重名、引用和变化中的消息。不能直接把正文前缀当发送者。
3. 进入/退出多选目前只做了人工诊断脚本验证，还没有写入生产读取链路。实现时应保留窗口布局、焦点和用户已有多选状态，并避免每次轮询反复切换。
4. avatars() 会将群聊 incoming 消息行的成员头像写到群会话头像缓存，覆盖真正群头像。需要分离群会话头像与成员头像，并修复已有缓存显示。
5. 群聊页面仍禁用回复形式选择并强制文字；定时任务编辑器仍只有原先接收范围。需增加指定联系人/群聊选择，更新说明、移动端布局和执行记录。
6. 检查群语音录制期间新消息的取消逻辑、发送回执和上下文中的语音转写；避免无关群成员消息干扰既有请求或定时发布。
