# 群聊最新消息与成员头像恢复（2026-10-20）

实机发现独立监听窗停在历史位置，主微信已经显示新消息，但监听窗只暴露旧消息和“新消息”按钮。空闲读取限制还暴露了成员缓存未跨工作进程恢复的问题：重新补全身份时整页内容标识变化，真正的新请求被快照比较错误归为历史。

监听会处理目标聊天窗原生的新消息标记。微信 4.1.15.53 声明了 InvokePattern，却不响应其调用；适配器向已核验 HWND 的精确标记位置发送一对窗口消息，不使用全局鼠标输入、焦点切换或剪贴板。标记消失才记录成功，同一标记失败不重复操作。

原生选择核验得到的成员证据按账号、群、窗口、微信进程及启动时间、原生行正文和成员头部像素持久保存。工作进程重启可被动恢复证据，头像仍按已核验成员保存；正文、成员头部、群或微信进程变化时不能借用旧身份。

新入站消息在独立读取游标中领取稳定标识。方向、成员或引用内容稍后补全，不改变该次入站的身份。快照中的其他历史行重排不把已确认的新请求降为历史；只有实际领取的新入站会带此标记。滚动离开最新位置后保留最新消息游标，跟随未读标记返回时以该游标识别新增部分。首次加载空帧不建立空基线，避免第一屏历史被当作新请求。

229 项相关回归通过，涵盖历史滚动、原生标识变化、空帧、成员补全导致整页身份变化、跨进程证据隔离、只触发一次、图片与引用问答。实机先核对并补处理一条曾被误标的用户测试，随后另一条新的 @ 请求直接自动处理、确认送达原群，无需补正。重连后成员身份仍保留，浏览器实测成员头像图片已加载。实机资料保存在被 Git 忽略的 `.panel-data/reports/`，其中补处理样例与正常新入站样例分别记录。
