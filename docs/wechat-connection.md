# 微信连接与消息可靠性

## 第一次使用

1. 启动并登录桌面微信，确认工作台右上角显示“微信已连接”。
2. 点击“添加联系人”，填写完整、唯一的微信备注以及联系人资料中的微信号。
3. 工作台会核对当前登录账号、联系人备注及微信号。不一致或存在多个同名结果时停止添加。
4. 添加时可勾选开启监听。连接时复用该联系人的独立聊天窗口；没有打开时，双击已核验的会话打开一次。首次导入窗口可见消息，此后的新消息持续同步。
5. 在聊天工作台输入文字，点击发送或按 `Ctrl + Enter`。发送直接复用绑定窗口、粘贴文字并点击微信的“发送”按钮；账号标识、会话标题和草稿均只读检查。发送前窗口失效会自动重新连接；已开始粘贴或发送后结果不明时保留待核对，不自动重发。
6. “仅监听”模式关闭回复；“全部暂停”阻止新的监听操作和发送，已经开始的 UI 操作可能仍完成。

点击“恢复运行”会自动连接所有已开启监听的联系人。窗口还在则直接复用；窗口已关闭则搜索完整备注、双击会话打开独立窗口，检查窗口标题并完成绑定后恢复监听。需要打开缺失聊天窗时，微信主窗口最小化会自动还原；收进托盘时直接调用微信托盘按钮的 UI Automation 激活接口，图标在隐藏区时先调用隐藏区按钮。此过程不依赖图标范围或鼠标坐标，避免 Windows 报错范围时误点网络、音量。微信停在公众号详情、通讯录等页面时，自动返回会话列表再搜索。无需手动展开微信或逐个打开联系人。恢复过程不打开“聊天信息”或点击联系人头像。排队消息先等待连接完成，连接失败时不会点击发送；单个联系人连接失败不阻止其他联系人连接。微信尚未登录、桌面锁定或同名联系人无法唯一识别时，面板显示对应原因。

右侧会话详情显示绑定微信号、账号、监听状态及中断提示。联系人管理支持检索、监听开关和移除。移除只影响工作台和本地记录，微信好友关系不变。

启动面板后按已保存的监听开关自动连接，微信稍后登录也会定期检查并继续连接。聊天窗关闭、UI Automation 元素失效等可恢复情况会按 1～30 秒间隔自动重连；暂停或关闭监听可阻止自动打开窗口。顶部显示实际已连接的会话数量。恢复连接期间仍可提交待发送文字，发送前会完成目标窗口连接；身份不一致、同名联系人歧义和微信已有草稿不会自动绕过。

联系人头像会从现有微信会话列表、聊天消息及首次核验时的头像控件读取，缓存在本机数据库中，统一显示于会话列表、聊天标题、消息旁、会话详情和联系人管理。后台每 30 秒被动检查可见头像，不搜索、点击或滚动；窗口收起、头像被裁切或画面不可读时保留缓存和文字占位。联系人管理中的“同步头像”会立即读取现有窗口，仅对尚无头像的联系人定位一次。自己发送的消息使用当前账号头像，不使用对方头像。

窗口截图、UI 控件及输入统一使用实际显示像素，适配不同显示缩放。头像须完整处于消息列表可见范围，避免读到输入区或标题栏。新消息初次显示不完整时先保留“方向待识别”，后续确认发送方会更新原记录；新的对方文字来信只触发一次 AI，历史消息和本人消息不触发回复。

## 真实微信连接的前提与当前实机检查

依赖 `pyweixin` 的 Windows UI Automation。微信进程存在不代表界面可操作。请保持已登录的 Windows 桌面可操作；锁屏、关闭独立聊天窗口或微信更新都可能导致监听中断。

**2026-10-11 更新：微信 4.1.15.53 实机已恢复 UI 控件访问。** 修正了搜索框名称为空和窄窗口折叠搜索区的兼容问题；已核验用户指定联系人并在微信窗口观察到测试消息。入站监听以对方账号实际发来新消息为准，不把历史或本人发言当作监听成功。若界面再次无法访问，可在“运行状态”点击“重启微信连接”展开主窗口。上游版本限制见下载的 [上游微信版本说明](https://github.com/Hello-Mr-Crab/pywechat/blob/main/Weixin4.0.md)。

当前实现不自动更改 Windows 无障碍设置、不登录其他账号，也未加入 OCR 收发适配器。

首次同步仅覆盖窗口可见的消息；监听窗口重建且无法确认连续性时，重新同步的内容标记为历史，并提示中断区间需要核对。UI Automation 不提供服务端送达回执，不能保证整个微信历史完全无遗漏。

独立窗口保持普通聊天状态。监听用 UI Automation 读取消息文字，用 Windows `PrintWindow` 读取同一窗口的头像位置来区分左右消息；其他应用遮挡窗口时也无需切换焦点。正常轮询不执行搜索、点击、滚动或多选，图像只在内存中分析。当前已验证浅色主题；头像被裁切、画面不可读或方向有歧义时保留“方向待识别”，不交给 Agent。

开启监听的聊天窗口最小化后，工作台会将它以不激活的方式还原并移到所有屏幕之外，显示“后台监听中”，让微信继续绘制消息。只在进入托管时移动一次，后续复用窗口读取。在工作台发送消息，或从任务栏打开该聊天时，窗口回到原位置；发送仍只操作目标窗口。暂停、关闭该联系人监听或正常退出面板，会恢复原位置并保留最小化。托管位置保存在本地；工作进程意外终止后，下次连接会核对微信进程及联系人再恢复位置。系统仍把托管窗口视为打开的普通窗口，因此它会出现在任务栏中。这种方式支持后台读取，锁屏或退出微信仍会中断监听。

联系人资料及微信号只在添加时核验。恢复运行和重启面板使用已保存的联系人绑定，并只读检查账号标识及窗口标题。同一微信进程、主窗口与账号标识均未变化时复用已核验的账号信息；微信重新登录或进程重启后重新核验当前账号一次。连续发送与监听均复用同一窗口句柄。

微信主窗口最小化或收进托盘时，只要当前账号已核验且独立聊天窗口仍存在，工作台可继续使用独立窗口，不要求先展开主窗口。发送时只还原目标聊天窗口。

## 发送状态

| 状态 | 含义 |
| --- | --- |
| 等待发送 | 已存到本地队列 |
| 正在发送 | 工作进程正在执行 |
| 已核对 | 微信窗口中观察到新增的本人消息，且输入框已清空；不代表对方送达或已读 |
| 待核对 | 发送可能发生，但不能证明结果；需在微信人工核对，不自动重发 |
| 发送失败 | 前置条件不满足等错误，需要处理原因 |
| 已取消 | 服务重启时取消尚未开始的发送 |

微信输入框有草稿时停止发送，避免覆盖或夹带内容。消息方向无法可靠识别时显示“方向待识别”，不会当作用户指令交给 Agent。
