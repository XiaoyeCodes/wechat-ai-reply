# 微信连接与消息可靠性

## 第一次使用

1. 启动并登录桌面微信，确认工作台右上角显示“微信已连接”。
2. 点击“添加联系人”，填写完整、唯一的微信备注以及联系人资料中的微信号。
3. 工作台会核对当前登录账号、联系人备注及微信号。不一致或存在多个同名结果时停止添加。
4. 添加时可勾选开启监听。连接时复用该联系人的独立聊天窗口；没有打开时，双击已核验的会话打开一次。首次导入窗口可见消息，此后的新消息持续同步。
5. 在聊天工作台输入文字，点击发送或按 `Ctrl + Enter`。发送直接复用绑定窗口、粘贴文字并点击微信的“发送”按钮；账号标识、会话标题和草稿均只读检查。发送前窗口失效会自动重新连接；已开始粘贴或发送后结果不明时保留待核对，不自动重发。
6. “仅监听”模式关闭回复；“全部暂停”阻止新的监听操作和发送，已经开始的 UI 操作可能仍完成。

## 切换微信账号

工作台跟随桌面微信当前登录的账号，不绑定某一个固定微信。登录后即使还没有添加联系人，也会核验当前账号一次；顶部显示当前昵称，悬停可查看微信号。微信退出登录或切换账号后，工作台自动重新识别并加载该账号保存的私聊、群聊、监听开关、Agent 绑定和回复方式。

新账号第一次使用时显示空会话列表，可直接通过“添加联系人”选择私聊或群聊并核验。原账号的聊天记录、头像和配置保留在本机；切回原账号后恢复其列表。相同联系人或同名群在不同账号下分别核验和保存，不自动搬移绑定。群聊的本人显示名以当前账号在群里的昵称为准，因此切换账号后也应使用对应账号的 @。

切号或退出登录会取消旧账号尚未发送的消息和未完成的会话 AI 任务；旧账号的会话不会在新账号下继续监听或发送。模型 API、Skill 和 Agent 库共用，联系人记录、群成员范围、引用图片及会话记忆由各账号的会话独立持有。定时发布只向当前账号符合条件的接收会话发送，已经开始的公共任务沿用原先选中的会话身份，不改投新账号的同名会话。

账号核验失败时显示具体原因，并等待“重启微信连接”重试，空闲轮询不反复打开本人资料。当前兼容中文界面中混用的“微信 / WeChat”导航名称及“微信号 / WeChat ID”资料标签。多个桌面微信主窗口同时存在时仍会提示先保留一个登录窗口，避免误选账号；这里支持在单个桌面微信中依次切换登录。

点击“恢复运行”会自动连接所有已开启监听的联系人。窗口还在则直接复用；窗口已关闭则搜索完整备注、双击会话打开独立窗口，检查窗口标题并完成绑定后恢复监听。需要打开缺失聊天窗时，微信主窗口最小化会自动还原；收进托盘时直接调用微信托盘按钮的 UI Automation 激活接口，图标在隐藏区时先调用隐藏区按钮。此过程不依赖图标范围或鼠标坐标，避免 Windows 报错范围时误点网络、音量。微信停在公众号详情、通讯录等页面时，自动返回会话列表再搜索。无需手动展开微信或逐个打开联系人。恢复过程不打开“聊天信息”或点击联系人头像。排队消息先等待连接完成，连接失败时不会点击发送；单个联系人连接失败不阻止其他联系人连接。微信尚未登录、桌面锁定或同名联系人无法唯一识别时，面板显示对应原因。

右侧会话详情显示绑定微信号、账号、监听状态及中断提示。联系人管理支持检索、监听开关和移除。移除只影响工作台和本地记录，微信好友关系不变。

启动面板后按已保存的监听开关自动连接，微信稍后登录也会定期检查并继续连接。聊天窗关闭、UI Automation 元素失效等可恢复情况会按 1～30 秒间隔自动重连；暂停或关闭监听可阻止自动打开窗口。顶部显示实际已连接的会话数量。恢复连接期间仍可提交待发送文字，发送前会完成目标窗口连接；身份不一致、同名联系人歧义和微信已有草稿不会自动绕过。

联系人头像会从现有微信会话列表、聊天消息及首次核验时的头像控件读取，缓存在本机数据库中，统一显示于会话列表、聊天标题、消息旁、会话详情和联系人管理。后台每 30 秒被动检查可见头像，不搜索、点击或滚动；窗口收起、头像被裁切或画面不可读时保留缓存和文字占位。联系人管理中的“同步头像”会立即读取现有窗口，仅对尚无头像的联系人定位一次。自己发送的消息使用当前账号头像，不使用对方头像。

窗口截图、UI 控件及输入统一使用实际显示像素，适配不同显示缩放。头像须完整处于消息列表可见范围，避免读到输入区或标题栏。新消息初次显示不完整时先保留“方向待识别”，后续确认发送方会更新原记录；新的对方文字来信只触发一次 AI，历史消息和本人消息不触发回复。

## 真实微信连接的前提与当前实机检查

依赖 `pyweixin` 的 Windows UI Automation。微信进程存在不代表界面可操作。请保持已登录的 Windows 桌面可操作；锁屏、关闭独立聊天窗口或微信更新都可能导致监听中断。

**2026-10-11 更新：微信 4.1.15.53 实机已恢复 UI 控件访问。** 修正了搜索框名称为空和窄窗口折叠搜索区的兼容问题；已核验用户指定联系人并在微信窗口观察到测试消息。入站监听以对方账号实际发来新消息为准，不把历史或本人发言当作监听成功。若界面再次无法访问，可在“运行状态”点击“重启微信连接”展开主窗口。上游版本限制见下载的 [上游微信版本说明](https://github.com/Hello-Mr-Crab/pywechat/blob/main/Weixin4.0.md)。

当前实现不自动更改 Windows 无障碍设置、不登录其他账号，也未加入 OCR 收发适配器。

首次同步仅覆盖窗口可见的消息；监听窗口重建且无法确认连续性时，重新同步的内容标记为历史，并提示中断区间需要核对。UI Automation 不提供服务端送达回执，不能保证整个微信历史完全无遗漏。

独立窗口保持普通聊天状态。监听用 UI Automation 读取消息文字，用 Windows `PrintWindow` 读取同一窗口的头像位置来区分左右消息；其他应用遮挡窗口时也无需切换焦点。正常轮询不执行搜索、点击、滚动或多选，图像只在内存中分析。当前已验证浅色主题；头像被裁切、画面不可读或方向有歧义时保留“方向待识别”，不交给 Agent。

开启监听的聊天窗口最小化后，工作台会将它以不激活的方式还原并移到所有屏幕之外，显示“后台监听中”，让微信继续绘制消息。只在进入托管时移动一次，后续复用窗口读取。在工作台发送消息，或从任务栏打开该聊天时，窗口回到原位置；发送仍只操作目标窗口。暂停、关闭该联系人监听或正常退出面板，会恢复原位置并保留最小化。托管位置保存在本地；工作进程意外终止后，下次连接会核对微信进程及联系人再恢复位置。系统仍把托管窗口视为打开的普通窗口，因此它会出现在任务栏中。这种方式支持后台读取，锁屏或退出微信仍会中断监听。

联系人资料及微信号只在添加时核验。恢复运行和重启面板使用已保存的联系人绑定，并只读检查账号标识及窗口标题。同一微信进程、主窗口与账号标识均未变化时复用已核验的账号信息；微信重新登录或进程重启后重新核验当前账号一次。连续发送与监听均复用同一窗口句柄。

微信主窗口最小化或收进托盘时，只要当前账号已核验且独立聊天窗口仍存在，工作台可继续使用独立窗口，不要求先展开主窗口。发送时只还原目标聊天窗口。

### 托盘隐藏与微信重启后的主窗口发现

微信的 Qt 主窗口收进托盘后，可能从 UI Automation 的桌面窗口列表中消失，即使查询时包含不可见窗口也找不到。微信重启后，上次保存的窗口句柄和进程信息也会失效。

主窗口发现现改为枚举 Windows 当前顶层窗口，再对每个微信进程窗口按实际 HWND 读取 UIA 类型。只有类型为 `mmui::MainWindow` 且进程身份一致的窗口才作为主窗口；不会根据“微信 / Weixin”标题误选独立聊天窗口，也不依赖旧账号缓存来发现窗口。账号缓存仍需通过进程、启动时间、主窗口及账号标识校验后才能复用。

短暂没有窗口时自动重试；登录页提示先登录；确实存在多个主窗口时停止选择并说明数量，防止串号。2026-10-17 实机验证了“主窗口隐藏、UIA 桌面列表无主窗口、没有账号缓存”条件下的发现、托盘激活及恢复监听。

## 发送状态

| 状态 | 含义 |
| --- | --- |
| 等待发送 | 已存到本地队列 |
| 正在发送 | 工作进程正在执行 |
| 已核对 | 微信窗口中观察到与本次正文匹配的新增本人消息；不代表对方送达或已读 |
| 待核对 | 发送可能发生，后台会继续核对回执；仍无可靠证据时保留人工核对，不自动重发 |
| 发送失败 | 前置条件不满足等错误，需要处理原因 |
| 已取消 | 服务重启时取消尚未开始的发送 |

微信输入框已有文字草稿时，默认先选中并剪切暂存，核对输入框清空后发送本次消息，再恢复原草稿；长回复分段发送时每段都沿用此流程。多行文字、Emoji 及可复制的富文本剪贴板格式会暂存。原草稿不会拼入消息或随本次回复发送。

发送按钮点击前发生错误时，会移除已核对的本次粘贴并恢复原草稿。窗口关闭、用户输入新内容或发送结果无法核对时，不覆盖变化后的输入框、不自动重发；剪切前已用 Windows DPAPI 加密备份原草稿，恢复成功后删除备份，未恢复的文件保留在数据目录的 `draft-recovery` 中。日志只记录暂存/恢复状态，不记录草稿正文。

消息方向无法可靠识别时显示“方向待识别”，不会当作用户指令交给 Agent。

## 切换窗口后的自动恢复（2026-10-18）

微信在窗口缩放、滚动或重新绘制时，会重新分配消息控件编号。工作台现在用连续、唯一的多条上下文对齐新旧控件，同时保留已核对的消息方向。不会只凭一条“你好”或相同短句去重。滚动到旧消息时保留原监听位置；短暂空白、无法对齐的画面先等待，连续三次仍无法对齐才记录历史中断。稳定后自动恢复监听提示，中断记录仍保留在日志中，不能据此认定中断期间的全部消息均已找回。

发送前检测到最近的鼠标或键盘操作，会先排队，按 2、4、8 秒间隔等待短暂空闲，再操作已绑定的微信聊天窗。粘贴和点击前再次检查前台窗口与遮挡。等待期间，同一联系人的后续分段不会越过前一段；其他联系人仍可正常处理。发送完成后，若焦点仍在程序操作的聊天窗，则尝试返回原窗口；用户已经切到其他窗口时不会再抢回焦点。

每次文字发送会先保存发送前的消息基线，并在点击前持久记录发送意图。如果点击后短时无法识别本人气泡，后台在点击后的 2 分钟内继续只读复核；只有正文、消息方向和新增消息身份均能核对，才自动改为“已核对”，并合并监听到的同一条回显。原先因等待回执而暂停的后续 AI 分段会在会话仍有效时继续发送。人工接管、取消或切换 Agent 后不会恢复旧任务。

已开始粘贴或点击发送的消息不会自动重发。旧版本没有记录发送基线的历史报错、超过复核时限、锁屏、微信退出或消息已滑出可读取范围等情况，仍可能需要人工核对。这里的“已核对”仅表示在本机微信中确认到对应的新增本人消息，不是微信服务端的送达或已读回执。

## 发送就绪与故障恢复

文字粘贴后会等待输入框回读一致且发送按钮启用，再核对账号、窗口类型与焦点，只点击一次。图片和 PDF 使用经过回读校验的标准文件剪贴板数据，并等待内联附件或发送对话框就绪。历史消息中的同名文件不能当作当前待发附件。

点击后的短暂 UI Automation 错误只会重读回执，不会再次粘贴或发送。文字、PDF、图片均保存发送前基线；新增本人消息已确认时才标记送达。回执迟到时最多后台复核两分钟，取消的任务和模糊的媒体气泡不会被自动恢复或重发。

短暂焦点占用、窗口遮挡和 UIA 失效采用退避重连，间隔从一秒增加到最多三十秒。身份不匹配、重名或账号冲突仍停止操作，避免串号或误发。

`tests/test_simulated_delivery.py` 在临时演示数据库中覆盖私聊/群聊的文字、PDF、图片完整收发。维护人员需要实机验证时，可停止面板后使用 `scripts/verify-self-delivery.py --send-to-self --account-id <当前账号>`；该脚本只向微信内置“文件传输助手”发送标记为自测的三条消息，没有联系人或群聊参数。测试数据保存在独立的 `.panel-data/self-delivery-*` 目录，不污染正式会话。

自测脚本会拒绝复用已打开的同名独立窗口；新窗口必须从微信搜索的“功能”分类打开，以免将备注同名的好友误作内置目标。
