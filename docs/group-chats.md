# 群聊监听与回复

在工作台点击“添加联系人”，将“会话类型”切换为“群聊”。填写微信中显示的完整群名，选择监听所有成员或指定成员；指定时每行填写一位成员的完整群内显示名。

默认“仅 @ 我”：只有符合成员范围、发送者已识别，且消息 @ 本人在群中的完整显示名时，才交给 Agent。也可选择“所选成员发言”，让这些成员的普通消息触发。本人群昵称可由微信设置读取；手动填写时界面会标明按填写值匹配，请与微信保持一致。

部分微信版本未通过辅助功能接口提供“我在本群的昵称”，即使屏幕上能看到该字段，也需要在添加表单中手动填写；否则无法识别“仅 @ 我”。微信 4.1.15 的成员面板没有旧版控件标识，现按其原生成员面板读取名单；备用成员选择列表无需先选中一行。两种方式仍要求名单人数与群人数一致，并拒绝指定成员重名。

添加后在右侧为群聊选择本地流程 Agent，开启监听，再选择“AI 自动回复”。AI 辅助模式会生成草稿，确认后发回原群。文字、原生语音、生成图片和技能结果复用现有微信发送队列，不会改发到成员私聊。先配置模型、技能、网页读取和生图能力，工具审批规则仍然有效。

例如，设置群“每日交流”、指定成员“张三”、本人群昵称“新闻助手”，触发方式为“仅 @ 我”。张三在该群发送“@新闻助手 执行每日新闻60秒”，Agent 将按技能取数、生成结果并回复该群；李四的消息不会触发，张三不带 @ 的普通消息也不会触发。

群消息显示发送者与已识别的 @ 提及。未知身份、引用中的 @、邮箱、@他人、历史同步和自己的发言不触发自动回复。群设置修改会取消旧运行并重新建立上下文边界。每个群、每位触发成员的上下文与记忆独立，不带入其私聊资料；无关群消息不取消其他成员已触发的请求。

开启“仅 @ 我”时，同一位已识别成员可以先发图片，再 @ 提问；图片本身不必带 @，也不会单独触发回复。同一轮紧接 @ 问题发来的图片，会在等待窗口内结合处理。连续、尚未回复的 @ 补充消息合并理解，其他成员的发言或图片不加入该轮。需配置图片理解模型，并保持原图可复制；获取失败时会说明图片尚未读出。也可引用文字或图片后提问，详见[引用问答](quoted-replies.md)；引用图片优先使用对应原图，引用内的 @ 不算本轮触发。

空闲监听和翻看历史采用被动读取，不反复进入多选或复制旧图。成员核验及原图读取由新的合格请求触发；仅 @ 模式下，未 @ 的群图片先记录，待新问题到来后按需读取。首次连接、历史滚动和窗口重绘本身不触发原图复制。

独立监听窗出现原生新消息标记时，会恢复到最新位置，不移动系统鼠标或占用剪贴板。已核验的成员身份可在同一微信进程内跨工作进程重连恢复；新消息的标识不随身份补全改变，避免正常请求被误标为历史。验证记录见[群监听恢复](design/group-listener-recovery.md)。

群聊按登录账号、唯一完整群名、群类型和成员信息核验，内部绑定标识不是微信真实群号。完全同名会话、指定成员重名或客户端未提供可用的发送者证据时，会停止相应操作并保留状态。群改名后请重新添加核验。

群聊可选择「跟随 Agent」「文字回复」或「语音回复」，音色与合成模型可独立设置。短文本转成微信原生语音；长内容、链接、列表或合成失败时发送完整文字。原生发送结果不确定时保留待核对状态，不重复改发文字。

在所绑定 Agent 的「定时任务」中新建任务，将「发布到」设为「指定联系人或群聊」，勾选此群。任务生成一次，按每个接收会话的设置投递文字、语音或图片。群聊不自动加入已有任务的私聊接收范围；私人关怀仍仅适用于私聊。工作台和可交互的微信桌面需保持运行。

微信 4.1.15 普通消息控件只提供正文时，程序临时进入原生多选，核对同一消息行切换前后完全相同的正文、原生 ID 和新增发送者字段，再退出多选。成员信息补全保留原消息的新入站状态，只触发一次。已核验结果按会话缓存；发送者区域变化会失效，不能仅凭相同正文和被复用的行 ID 继承其他成员身份。正在输入草稿、录音或使用多选时会等待。群头像仅取自会话列表/搜索结果，消息内成员头像单独保存。

自动化验证使用演示群、假 UIA 树和模拟模型；2026-10-20 在用户指定测试群完成文字发送、定时生成并发送原生语音的实机核对，并验证成员与头像读取。微信升级可能改变控件，连接以添加时的核验和运行状态为准。

同日补充验证：9 轮真实模型隔离对话覆盖聊天、回忆、图片与细节追问、Skill 加载及成员身份/记忆隔离；测试群中新收到的书籍图片已自动识别并回复原群，标记测试图片已核对发送，一次性任务实际加载 Skill 后按时发送原生语音。此处不代表每个外部接口均已逐一实测；群聊当前限本地流程 Agent，私人关怀与个人提醒不会直接发布到群里。
