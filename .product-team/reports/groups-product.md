# G1 群聊指定成员 @ 触发验收与测试计划

用户范围由总协调转达：添加群组监听，可指定群内某成员；该成员实际 @ 当前微信账号时执行所绑定 Agent 的正常处理流程，结果发送原群。延续既有 Agent/工具/技能/AI辅助和自动模式。不创建真实测试群，不向真实群发消息。

## 入口与核心流程

联系人入口增加私聊/群聊选择。群聊填写可在微信中核验的群名称、允许触发的成员名单、只在 @ 本人时触发的选项和本人群昵称。成功核验群后绑定 Agent、开启监听和 AI 自动回复；新消息必须有可信发言人及可信 @ 本人证据，才可进入原有 Agent 流程。生成、技能、图片和工具审批沿用既有机制；发送前仍检查原群绑定与开关配置。

## 稳定验收条款

| ID | 可操作通过标准 |
| --- | --- |
| G1-01 | 私聊默认 chat_type=direct，原添加/核验流程正常。群聊 chat_type=group 只需要群名称及群配置，无须伪造微信号；必须调用群专属核验，不能将同名私聊当群保存。 |
| G1-02 | 指定成员发出新消息，并有可信发言人和可信 @ 本人标记时触发一次 Agent；空名单表示允许所有已验证成员。名单、本人群昵称及选项的非法输入返回明确 4xx。 |
| G1-03 | 非指定成员、未知/未验证sender、无 @、@他人、引用中的 @、邮件地址中的 @、正文伪装成员名前缀、未知/未验证mention 均不能冒充合法触发。 |
| G1-04 | 初始历史、自己发出的消息、系统事件不触发；普通无关成员的新发言不取消已触发任务，不污染本轮上下文、附件或长期记忆。 |
| G1-05 | 同群不同成员即使发完全相同文字，也保持两个消息身份；UI控件重建或消息裁切时不得将不同发言人合并/对齐，后续补齐证据也不重复触发。 |
| G1-06 | 合格触发执行原有 Agent 流程与技能/工具权限。输出仅在发起群排队和核对；无关群或私聊不能收到。群聊AI辅助仍为草稿，不自动发送。 |
| G1-07 | 不同群、群与私聊之间的聊天及记忆隔离；不得把任一成员私聊记忆载入群回复。上下文中的群发言人必须可信且可区分。 |
| G1-08 | 修改成员/本人昵称/@限制、停用监听、切换模式/Agent、全局暂停及关闭AI会使旧生成或排队回复失效；重新开启不能恢复旧授权。 |
| G1-09 | 公共 Agent 定时任务本版仅投递私聊，群聊即使绑定同Agent并开启listening+ai_auto也必须被排除，避免新增群监听后自动收到既有广播。 |
| G1-10 | 原私聊消息、快照、上下文及每日新闻定时任务保持回归通过。群相关验证使用假bridge/UI树、假模型和临时SQLite；明确区分模拟与真实微信核验。 |

## 重点实现风险

1. 接收资格过滤必须覆盖事件生成、AI收集、latest_id、连续消息unanswered、contact_context、图片附件选择和发送前守卫。仅在最初入口过滤会导致不合格发言抢占/取消任务，或进入实际模型输入。
2. sender显示名必须来自微信消息行结构，不能从正文的“成员名：”解析。@标记优先使用UIA实体；总协调已确认可使用独立正文中完整可见@昵称及严格边界识别，记录mention_source=visible_text。不能使用宽松text.contains('@昵称')，必须排除引用、邮件地址、伪前缀及@其他人。
3. snapshot identity/compare/align现有语义主要为文本+方向。群消息需要把发言人身份及可信程度纳入匹配，不能将相同正文跨发言人复用。
4. 群名称、本人群昵称、成员群昵称可能重名或变化。核验不足时应清楚提示并保守不触发，不把猜测写成已核验。
5. 群contact本身是发送边界；群成员不是私聊contact。不能为群发言自动查找同名私聊、复用私聊contact_id或其记忆。
6. 群配置必须参与运行revision。工具或生图耗时后改配置，不能继续把旧结果发到群。

## 独立测试方案

待合同稳定后建立 `tests/test_group_chats.py`。按以下层次覆盖：

- API：群添加走inspect_group，省略wechat_id，私聊既有校验仍生效；群配置保存、读取、非法参数与修改失效。
- SQLite/AI：使用含sender_verified/mention_verified的假入站消息，参数化合法/非法资格；执行假模型并检查只在原群排队；AI辅助为草稿。
- 上下文：设置三个成员的独特私密marker，不合格成员、其他群和私聊marker不得进入模型输入；无关成员发言不取消合法pending/queued任务。
- 快照：同文不同sender、控件重建、裁切、证据后补、历史/系统/本人消息；断言不误对齐且不重复触发。
- 生命周期：生成中/排队后改群配置或关闭功能，旧回复失效；群不进入Agent公共定时eligible或本次收件人快照。
- 桥接/运行时：由backend负责群UI树与群专属窗口核验，独立复跑其假bridge测试；不凭模拟声称当前真实微信版本已支持。

## 合同状态

已确认字段：contact.chat_type=direct|group、group_members=list[str]、group_mention_only=true、group_self_name=str；message.sender=str、sender_verified=bool、mention_me=bool、mention_verified=bool、mention_source=str。

群记忆scope按群contact+可信sender隔离；run.state.group_sender保存触发成员。每条合格群消息独立create_run，不通过单contact inbox合并，不读无关群历史；dispatch同群串行。同成员后续触发可使旧run过时，其他成员发言不能取消旧run。latest_id按group_sender及群资格筛选，发送守卫检查同成员最新触发。公共定时eligible默认排除group。
