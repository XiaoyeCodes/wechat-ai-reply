本次为 Agent 模拟体验官评估，操作服务为 http://127.0.0.1:8771/，数据目录为 .panel-demo-data/group-chats-qa。未操作真实 8766 工作台、真实微信或付费模型。

## 实际完成的操作

- 打开添加联系人弹窗并切换群聊，确认不显示或要求微信号，默认「所有成员」「仅 @ 我」。
- 添加「设计讨论群 QA」，填写指定成员张三、李四，以及本人群内名小助手。实际保存后会话列表、聊天标题与详情均显示群聊身份，资料不把内部绑定 ID 当成群号。
- 详情中显示「按填写的群内昵称匹配 @」，明确 user_config 的来源，没有声称自动读取并核验本人昵称。
- 把成员草稿增加王五但不保存，再通过演示界面以张三身份注入带 @ 的消息。事件刷新后未保存草稿仍完整保留，界面显示「有未保存的修改」。聊天气泡显示张三及经验证的 @我 标识。
- 将触发规则改为所选成员发言并保存，成功提示出现，聊天标题与规则摘要更新为指定 3 位成员、成员发言触发。
- 打开群表单后切回联系人，实际读取 DOM 确认微信号重新显示且 required=true，隐藏群成员 textarea required=false，私聊必填行为保留。
- 以 390×844 视口检查添加群聊弹窗，宽度 370，clientWidth 和 scrollWidth 均为 368，无横向溢出；字段可滚动，取消与添加按钮固定可见。完成后已恢复浏览器原尺寸。
- 关闭 QA 群监听，并经 API 与 UI 双重确认 listening=0、监听开关关闭、页脚 0 个会话监听中。

## 修复及复查

群消息输入区原有「发送前核对微信号」文案容易让用户误认群聊也需要个人微信号，现按会话类型改为「发送前重新核对群聊」，已重新加载并验证。

群 Agent 下拉只提供当前支持的工作流类型；零工作流 Agent 时提供创建引导。群规则草稿避免被后台同步覆盖；错误保留在原表单，不丢失输入。未发现阻断新增、编辑或演示群消息查看的界面问题。

## 覆盖边界

本角色验证界面配置、规则持久化、演示消息来源展示、刷新草稿保持及桌面/手机布局。真实 Windows 微信的成员与 @ 识别、实际模型生成和原群自动发送由独立 bridge/AI 测试及总协调集成测试覆盖；本体验未执行真实微信群推送，不把演示结果等同真实微信实发。
