# Agent 定时任务体验复查

评估角色：Agent 模拟用户体验官。浏览对象为隔离演示服务 http://127.0.0.1:8771/；不是用户验收或真实访谈。真实 8766 工作台、联系人和微信发送均未改动。

## 实际操作与证据

1. 从 AI 中心进入自动任务。零 Agent 时看到「先创建一位工作流 Agent」以及「前往我的 Agent」，新建按钮不可用，未伪装支持其他引擎。
2. 经本地 API 在 8771 添加一套 QA 假模型、每日新闻技能和工作流 Agent。模型指向 127.0.0.1:19999/v1，未调用模型，未使用真实密钥。
3. 通过实际浏览器表单创建四种任务：每天、每周一、一次性日期和自定义 Cron（30 8 * * 1-5）。保存成功，卡片正确显示规则与 Asia/Shanghai。所有任务均停用。
4. 在每日任务选择已绑定的新闻技能并点击填入模板，正文包含「9:16 手机竖版新闻卡片」。模板可编辑，未直接生成付费图像。
5. 启用每日任务后，卡片展示下次时间和零收件人说明；立即运行不可用。随后停用，确认已启用任务数回到零。
6. 切换联系人关怀，原添加关怀日程入口及说明仍可见。
7. 桌面新建表单的标题、字段、固定保存区无溢出；字段区可滚动。保存后的成功反馈和停用状态清晰。截图为 schedule-desktop-editor.png。
8. 检查总协调生成的 output/agent-schedules/mobile.png（390 像素宽）：字段单列、按钮完整、固定保存区可见，未发现横向溢出。此处是对实际自动化测试截图的视觉复查，不冒称本人调整了浏览器窗口。总协调另有独立 UI 测试覆盖两位 Demo 收件人共享一次结果的投递与历史；本角色未自行向微信投递。

## 已修复的问题

- 轮询在数据未变化时仍重建卡片，造成按钮元素和键盘焦点失效。现在只在数据变化时更新任务列表；历史也按内容变化更新，用户展开的文字结果不会被无变化轮询收起。失败后重试会正确恢复列表。
- 与接口校对后，将重复任务 at 设为空字符串、正文最大长度设为 8000，避免保存时字段校验失败。
- 原运行完成文案「测试完成」改为「已完成」，定时生成的运行详情显示任务类型，避免与测试台混淆。

## 结论及限制

当前体验没有阻断任务配置的问题。前端 ES module 语法检查及 git diff --check 均通过。四条 8771 QA 任务全部停用，未遗留启动中的测试定时推送。原始图像生成、真实模型授权与真实微信发送依赖用户环境，未通过本次体验进行实发。
