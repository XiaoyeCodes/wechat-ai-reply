# Agent 定时任务验收补充

确认范围见 `../brief.md`。新增任务独立于私人关怀日程。首版不自动建立任何真实推送任务；未指定时间或 Agent。

## 核心流程

用户在 AI 中心选择 Agent，填写任务名称、指令、时区及一次性时间或重复规则，保存后可查看下次执行、启停、编辑、删除和立即运行。到期时只生成一份结果，完成后向符合条件的联系人逐个进入串行发送队列。运行历史同时展示生成状态、工具确认状态和各收件人送达状态。

## 可操作验收条款

| ID | 检查与通过条件 |
| --- | --- |
| AC-01a | CRUD 只接受存在且可运行的 Agent、非空名称/指令、合法时区和合法调度规则；不合法时间/时区返回可理解的 4xx，不出现服务 500。编辑后下次时间按新时区规则计算。 |
| AC-01b | 一次性时间能明确表达时区，重复任务显示该时区的下次执行；启用、禁用、删除及立即运行可在界面完成。 |
| AC-02a | 两个及更多合格联系人只对应一次模型/工具工作；共享同一份正文或相同图片字节，不能每人重新生图。 |
| AC-02b | 生成阶段使用独立任务上下文；不得读取任一联系人的私人聊天、档案或长期记忆，再广播给其他人。 |
| AC-02c | 确认型工具仍进入 waiting_approval；批准前不执行工具或投递。拒绝后任务取消，历史保留原因。 |
| AC-03a | 收件人必须同时满足同 Agent、listening=true、mode=ai_auto；manual、ai_assist、listen_only、未监听和绑定其他 Agent 均不能收到。 |
| AC-03b | 从任务生成到发送可能经过较长时间，发送动作前应重新检查当前联系人配置、任务/Agent 启用、全局 AI 开关及暂停状态。排队后再关闭配置必须阻止发送。 |
| AC-03c | 多人投递的状态互不误伤：甲失败或改为人工模式，乙仍可获得自己的准确状态；不因其中一人确认而把所有人标成送达。 |
| AC-04a | 长文本按现有微信限制拆分，完整顺序排队；图片沿用现有图片发送并核对。任务级生成完成与逐人发送成功分别显示。 |
| AC-04b | 发送中/结果不确定不能显示成功；失败后不自动重复点击发送，不得将私人聊天中的图片当成本次共享产物。 |
| AC-05a | 同一到期时刻连续或并发 tick 只创建一个 occurrence 和一次生成；立即运行也有单独运行身份，执行中重复操作不重复生成。 |
| AC-05b | 重启后 running 标为不确定，旧 queued 取消或明确跳过；不得重放不确定或发送中的内容。重复规则跳到未来时刻，不循环补发历史任务。 |
| AC-05c | 过期任务有明确定义的容忍窗口；过期被跳过且记录原因。已生成内容发送前也有截止时间，不能隔日推送旧新闻。 |
| AC-06a | 无合格收件人时给出“无符合条件的联系人”状态，不产生投递，也不为零收件人付费执行生图。 |
| AC-06b | 未配置模型、没有 Agent、停用 Agent、无效配置或工具错误均可从历史定位，不能沉默失败。 |
| AC-07a | 新增单元/接口测试使用临时 SQLite、假模型与假图片，不连接真实微信、不使用付费模型或生图；原关怀日程至少运行核心回归。 |

## 已识别的实现风险

1. 现有 `create_run(contact_id=...)` 会读取联系人聊天上下文和私人记忆。广播任务必须使用 contact_id=None 或等价独立命名空间。不能选第一个联系人作为生成样本。
2. 现有 `ai_send_valid` 根据 `ai_runs.contact_id` 联表；广播生成运行若没有 contact_id，直接复用同一 run_id 给多人会被拒绝。应有逐人投递运行或单独授权路径，不可取消现有检查。
3. 现有 `image_delivery.deliver` 校验 run.contact_id 与收件人相同并检查生成 media 的 scope。共享图片需要显式绑定到同一次广播产物，不能通过放宽所有 scope 校验解决。
4. 现有关怀支持 ai_assist，与本需求只接收 ai_auto 不同。必须新增独立 eligibility，不能复用后扩大收件范围。
5. 现有消息回执会按同一 ai_run_id 汇总所有 parts。若广播多人共用 run_id，会把不同人的状态混在一起；逐人 identity 必须保留。
6. 单纯只在定时 tick 检查开关不足以防止排队后关闭，发送前守卫必须包含任务及 Agent 当前状态。

## 测试准备范围

独立验证矩阵覆盖任务 CRUD/时区、多人一次生成、私人信息隔离、目标筛选、发送前配置变化、全局开关、文字/图片、确认型工具、到期去重、重启不重放、过期跳过和零收件人。API/实现合同落定后编写 `tests/test_agent_schedules.py`。真实模型质量、生图最终画面以及真实微信送达留为明确未执行项。

## 已落定的首版边界

- 首版支持工作流 Agent。Hermes 的专属联系人电脑授权与其他原生 Agent 引擎未扩展至公共广播，界面需明确支持范围。
- 新任务默认停用，停用时无下次时间；立即运行必须先启用，并满足总开关与收件人条件。
- 开始执行时冻结候选收件人，生成完成后再取资格交集；生成途中才开启订阅的人从下次开始接收。
- 到期任务超过 5 分钟跳过；一次公共运行内容有效 1 小时，过期不能继续生成或投递。
- 普通新聊天可以和广播独立进行；监听/自动回复/Agent 绑定发生变化会使旧投递失效，重新开启也不能恢复旧授权。
- 保留 Agent 静态任务指导与风格；联系人历史、档案、长期记忆及私人模板上下文不进入公共任务。
